# HealthSys｜智慧健檢管理系統

### 讓健檢流程看得清楚，讓日常操作更從容。

> **從預約、報到、檢查追蹤到帳務查詢，建立連貫的健檢工作空間。**  
> 以直覺介面呈現資訊，以情境引導降低學習負擔，並以自然語言操作作為智慧服務的延伸方向。

---

## 01｜系統定位：圍繞健檢工作的整合平台

HealthSys 將健檢中心的日常工作整合為一致的操作環境，讓櫃檯、護理、檢查、專案、帳務及管理人員，依各自的工作情境查閱與維護資料。

**核心功能主軸**

| 工作主軸 | 功能內容 | 使用價值 |
| :--- | :--- | :--- |
| 營運總覽 | 人數統計、狀態比例、受檢者清單與條件查詢 | 從整體狀況快速聚焦到個別受檢者 |
| 預約與報到 | 個人預約、團體名冊、掛號與報到作業 | 串起受檢者到院前後的服務流程 |
| 檢查與報告 | 檢查進度、流程節點、檢查結果與報告查閱 | 集中掌握個案目前的檢查狀態 |
| 企業與專案 | 公司資料、健檢專案、組套及特殊作業設定 | 支援企業健檢與不同服務方案 |
| 醫令與套餐 | 健檢醫令、院內組套與套餐內容維護 | 統一管理檢查項目及方案內容 |
| 費用與帳務 | 專案帳目、應收與扣款明細、Excel 匯出 | 讓費用構成與核對工作更清楚 |
| 系統管理 | 員工、角色、功能權限與基本資料設定 | 依工作分工管理系統使用方式 |
| 個人化介面 | 主題、配色、字級、密度與表格顯示調整 | 配合不同使用習慣與工作環境 |

> **版本狀態**：目前工作版本以示範資料呈現功能與操作情境；智慧客服目前提供對話介面與服務狀態提示。本文第 05～07 節的自然語言查詢及 AI Agent 代操作為功能設計藍圖，尚未代表本版本已啟用。

## 02｜核心功能：讓每個工作環節彼此銜接

### 2.1 營運儀表板｜先看全局，再處理細節

- **狀態統計卡片**：呈現總人數、已預約、已掛號、已報到、檢查中、佔名額及已取消的人數與比例。
- **圖像化狀態分布**：以圓形統計圖呈現查詢範圍內的分布，並可展開查看各狀態人數與百分比。
- **條件式受檢者查詢**：依預約日期區間、狀態與頁面提供的搜尋條件縮小資料範圍。
- **受檢者資訊聯動**：選取清單資料後，查閱對應的個人資訊與檢查內容，保持同一位受檢者的操作脈絡。
- **查詢狀態回饋**：以載入提示、查詢結果與錯誤訊息，清楚交代目前畫面狀態。

### 2.2 預約管理｜兼顧個人服務與團體作業

- **個人預約建檔**：整合受檢者查找、基本資料、預約資訊與方案選擇。
- **預約清單管理**：集中查看預約紀錄，搭配狀態標示與排序功能辨識工作順序。
- **團體預約管理**：以團體及專案情境整理受檢名冊，減少大量人員逐筆處理的負擔。
- **名冊匯入工作區**：提供匯入範本、檔案選擇、拖曳上傳入口與匯入結果統計。
- **匯入資料檢視**：以名冊表格呈現人員資料及處理狀態，方便檢視需要確認的內容。
- **費用配置介面**：在預約情境中呈現方案與相關費用欄位，支援檢視及調整。

### 2.3 掛號與報到｜把到院服務集中在工作畫面

- **今日報到清單**：集中呈現當日受檢者及報到相關資訊。
- **個別報到作業**：選取受檢者後查看預約內容，進行對應的掛號或報到操作。
- **狀態辨識**：以文字與視覺標籤區分受檢者目前的處理階段。
- **資料核對**：在執行作業前確認受檢者身分、預約日期與方案，降低選錯人的機會。

### 2.4 檢查流程與報告｜讓進度與內容一起被看見

- **流程節點顯示**：以已完成、進行中與待檢查呈現各檢查階段。
- **個案完成比例**：顯示受檢者的檢查進度，便於辨識尚未完成的流程。
- **檢查工作清單**：依條件檢視受檢者及對應的檢查資訊。
- **報告內容查閱**：集中呈現相關檢驗或影像報告內容，配合個案切換查看。
- **細節閱讀輔助**：透過內容區塊與放大閱讀等互動設計，方便查看較長的報告。

### 2.5 企業與健檢專案｜將複雜設定拆成清楚步驟

- **公司資料維護**：管理企業客戶基本資料，提供專案建立與服務安排的資料基礎。
- **專案清單與明細**：集中查看專案資訊，進入明細進行後續管理。
- **分步建立專案**：依序完成基本資料、組套與醫令、特殊作業、內容確認及完成頁面。
- **院內組套選用**：查找既有組套，選取後納入專案，並檢視內容與價格。
- **專案內容確認**：在完成前彙整設定，讓人員再次核對方案內容。
- **內容來源辨識**：區分院內匯入與自行加入的項目，並以鎖定標示提示受限制的內容。

### 2.6 套餐與醫令維護｜建立一致的方案內容

- **健檢醫令管理**：查詢與維護檢查項目、分類及相關設定。
- **院內醫令查找**：提供院內組套與醫令的查閱入口。
- **套餐內容管理**：整理套餐與檢查項目的對應關係。
- **關聯資料保護**：對於受其他功能引用的資料，提示限制或阻擋不適合的刪除操作。

### 2.7 帳目查詢｜讓金額構成一目了然

- **專案帳務檢視**：依查詢條件呈現專案及組套、醫令對應的金額。
- **費用分項呈現**：分別顯示總金額、應收金額、優待金額、記帳金額與轉欠金額。
- **欄位即時說明**：透過說明提示交代總金額與應收金額的定義。
- **總計與分頁**：提供彙總金額及每頁專案數調整，方便閱讀大量帳目。
- **Excel 匯出**：將帳目查詢內容輸出為可供核對與整理的檔案。

### 2.8 人員與權限｜讓功能配置對應工作分工

- **員工帳號管理**：查看及維護人員資料、角色與使用狀態。
- **角色管理**：依櫃檯、醫師、帳務或管理等工作需求配置角色。
- **功能權限設定**：以功能層級呈現可查看、可覆核等權限設定。
- **基本資料維護**：集中管理健檢區域、流程與常用資料，維持操作選項的一致性。

## 03｜UI 設計：漂亮，也讓工作更好完成

### 3.1 穩定的工作框架

**側邊功能導覽 × 主工作區 × 情境明細**構成清楚的使用動線。側邊選單標示目前所在功能，子選單依工作分類展開，讓使用者知道自己在哪裡、下一步可以去哪裡。

### 3.2 一眼辨識資訊層級

以統計卡片承載摘要、表格呈現清單、明細區展開內容。標題、留白、圓角與重點色彩共同建立閱讀順序，讓使用者先找到關鍵，再進入細節。

### 3.3 用顏色與文字共同表達狀態

預約、掛號、報到、檢查中與取消等狀態，都有對應的文字及視覺提示。圖表與清單彼此呼應，協助辨識工作進度；即使採單色主題，也能以文字與深淺保留區別。

### 3.4 清楚的選取光棒

資料列透過選取底色、邊界與光棒效果凸顯目前對象，協助使用者在密集表格中維持視線焦點。部分表格亦提供方向鍵切換，適合連續檢視資料。

### 3.5 能配合人的介面

| 個人化項目 | 可選內容 | 適用情境 |
| :--- | :--- | :--- |
| 主題模式 | 淺色、深色、灰色、單色、跟隨系統 | 配合環境與閱讀偏好 |
| 主色設定 | 預設色票、自訂調色盤、色碼與亮度 | 建立熟悉的工作視覺 |
| 字體顯示 | 字級及文字顏色調整 | 改善閱讀辨識 |
| 元件密度 | 舒適、標準、緊湊 | 平衡留白與資訊量 |
| 表格列高 | 可調整資料列高度 | 配合大量資料檢視 |
| 圓角設定 | 調整元件圓角大小 | 配合介面風格偏好 |
| 主題預覽 | 預覽表格、按鈕、狀態及帳目配色 | 套用前先確認整體效果 |

### 3.6 操作過程有回應

查詢時顯示進度，完成後呈現結果；沒有資料時交代原因，發生問題時顯示訊息。重要設定與刪除動作搭配確認提示，讓使用者能判斷目前狀態與下一步。

## 05｜智能查詢設計藍圖：從輸入條件，到說出需求

> **功能規劃｜尚未啟用**  
> 以下描述智慧查詢的目標能力與互動情境；目前版本的智慧客服尚未提供即時資料查詢。

智能查詢的設計目標，是讓使用者直接說出想知道的事情，由智慧助理整理查詢條件、呈現資料，並接續到相關工作畫面。

### 5.1 理解日常語句

使用者可用自然語言描述日期、對象、狀態與查詢目的。例如：

- 「幫我找今天已預約、還沒報到的人。」
- 「查看這家公司本週的健檢預約。」
- 「列出目前檢查中的受檢者。」
- 「查這個專案的應收、優待與記帳金額。」

### 5.2 將口語需求整理成明確條件

智慧助理將「今天」「本週」「這家公司」等描述轉為可核對的條件摘要，顯示日期範圍、公司、專案與狀態，讓使用者知道查詢依據。

### 5.3 不足的資訊，適時補問

當姓名重複、專案不明或日期不足時，先提供候選項目或詢問缺少的條件。使用者選定後再繼續，讓查詢結果對應正確對象。

### 5.4 延續同一段工作脈絡

前一次已選定公司、專案或受檢者後，可接著說「只看未報到」「打開他的檢查進度」「改成下週」，延續目前條件並顯示調整結果。

### 5.5 回答之外，也能帶到工作畫面

查詢結果以摘要、清單或明細卡片呈現，並提供「查看預約」「開啟個案」「查看帳目」等後續入口，讓資訊查找自然銜接下一步工作。

## 06｜AI Agent 設計藍圖：讓一句話變成可確認的操作

> **功能規劃｜尚未啟用**  
> AI Agent 的目標是協助操作系統；本版本尚未提供自然語言指令執行、跨頁代操作或自動完成報到等能力。

### 6.1 理解目的，安排操作

當使用者提出「幫這位受檢者完成報到」時，Agent 應先辨識對象、查閱預約及目前狀態，再呈現可執行的動作。

**目標互動流程**

**說出需求 → 確認對象與條件 → 呈現操作摘要 → 必要時確認 → 執行操作 → 回報結果**

### 6.2 智能協助的功能層次

| 功能層次 | 目標能力 | 使用者可見的結果 |
| :--- | :--- | :--- |
| 查找 | 依自然語言查詢日期、狀態、公司及專案 | 符合條件的資料清單 |
| 導航 | 開啟對應頁面或指定個案明細 | 直接進入相關工作位置 |
| 填寫 | 將已確認的資訊帶入表單 | 可檢視、可調整的預填內容 |
| 作業 | 在條件符合及必要確認後執行指定動作 | 明確的成功、失敗或待處理狀態 |
| 串接 | 將查詢、開啟、填寫及提交接成連續任務 | 任務進度與每一步的處理結果 |

### 6.3 對人、對資料、對動作

- **對象清楚**：操作前呈現受檢者、預約日期與專案，避免只憑姓名判定。
- **範圍清楚**：批次任務列出條件、筆數與處理對象。
- **變更清楚**：資料異動前顯示即將修改的內容。
- **權限一致**：依使用者可用功能處理任務，無法執行時說明原因。
- **結果可核對**：以實際處理結果回覆，區分已完成、部分完成及未完成。
- **中斷可接手**：遇到資料不足或狀態限制時，停在清楚的步驟並提供後續入口。

### 6.4 智能帶來的實際體驗

**少記路徑**：直接描述目的，由 Agent 協助定位功能。  
**少填重複資料**：延續已確認的對象與查詢條件。  
**少做來回切換**：將相關畫面與操作接成連續任務。  
**保留掌握感**：重要內容先看得見，處理結果能核對。

## 07｜情境展示：一句需求，接續一段工作

> 下列為智能查詢與 AI Agent 的規劃情境示例。

| 使用者的需求 | 預期智能協助 | 預期呈現 |
| :--- | :--- | :--- |
| 「今天還有誰沒報到？」 | 整理當日預約及未報到條件，查找符合資料 | 人數摘要、受檢者清單與報到入口 |
| 「打開這位受檢者的檢查進度。」 | 確認目前選取個案，開啟流程資訊 | 已完成、進行中及待檢查項目 |
| 「幫我建立這家公司的健檢專案。」 | 確認公司，收集必要資料並帶入專案建立步驟 | 可逐步核對的專案內容 |
| 「查看這個專案的帳目，再匯出。」 | 確認專案及日期，整理帳務結果並提供匯出 | 費用明細、總計與下載結果 |
| 「把畫面改成深色，字再大一點。」 | 顯示預計調整的外觀設定並提供預覽 | 可確認的主題與字級變化 |
| 「幫我報到這位受檢者。」 | 核對身分、日期及狀態，呈現報到摘要後執行 | 實際報到結果及更新後狀態 |

**示例對話｜查詢接續報到**

> **使用者**：幫我找今天還沒報到的受檢者。  
> **智慧助理**：我會以今天的預約為範圍，查找尚未報到的資料，並顯示查詢條件與清單。  
> **使用者**：打開清單中的這一位。  
> **智慧助理**：顯示所選受檢者的預約資訊與目前狀態。  
> **使用者**：幫他報到。  
> **智慧助理**：呈現受檢者、預約日期與專案供確認，完成作業後回報實際結果。

## 08｜整體產品價值

### 對第一線人員：資訊集中，操作有方向

以清單、狀態、明細與流程引導支援日常作業，協助人員掌握目前對象與下一步工作。

### 對專案與帳務人員：內容清楚，核對有依據

整合公司、專案、組套、醫令與費用資訊，讓方案建立、資料維護與帳目整理有一致的工作入口。

### 對管理者：看得見整體，也查得到細節

透過儀表板、狀態分布與查詢清單掌握工作概況，再深入個案、專案與帳目明細。
